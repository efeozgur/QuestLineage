# CLAUDE.md

QuestLineage is a WoW addon (Lua 5.1, Interface 16001, client 1.60.1 "World of Warcraft: Forever"): quest chain trees built on the QuestieDB addon. It is independent of ForeverTrail (a separate repo by the same author). No build step; the repo is linked into `Interface\AddOns\QuestLineage` with a junction, so edits take effect on `/reload` (new files need a full game restart).

## Rules

- **Interface language:** English by default. Turkish is an option that only takes effect while WoWTR is loaded (`QL.UseTurkish()`). Every user-facing string goes through `QL.L("English text")`; add its Turkish to the `TR` table in `Locale.lua`. Quest titles/objectives go through `QL.QuestTitle` / `QL.QuestObjectives` (WoWTR's `QTR_QuestData` first when Turkish, else QuestieDB). Fonts: the addon ships Inter (SIL OFL 1.1, `Media/Fonts/` with `Inter-OFL.txt`): `T.FONT` regular, `T.FONT_BOLD` semibold, set through `T.SetFont(fs, size, bold)` (falls back to WoWTR's Inter, then the game's Arial). The client's Arial Narrow and the game's tooltip font have no Turkish letters on this build, so: never use the game's fonts for QuestLineage text, and never use `GameTooltip` for QuestLineage's own tooltips; use `QL.Tip()` (own tooltip, same SetOwner/AddLine/Show/Hide calls; it closes itself when its owner is hidden, and an `ANCHOR_CURSOR` tip closes when `PlaceAtCursor` has not been called for 0.4 s, so a hover driver that stops (a map closed under the cursor) cannot leave it on screen). A local function used by a hook defined above it must be forward-declared (`local hover` ... `function hover`), or the hook calls a nil global. Item tiles are the exception (the game draws items). Lines QuestLineage adds to the game's NPC tooltip get the theme font and are restored on `OnTooltipCleared`.
- **QuestieDB only through its public API** (`LibQuestieDB.Quest/Npc/Object/Item.Get(id, field)`, `GetAllIds()`, `RequireContract(4)`), via the wrappers in `Data.lua` (`QL.Q/N/O/I`, pcall-guarded). Never read or change QuestieDB's or Questie's files.
- **No third-party code is copied in.** Polestar (GPL) and Queston Forever (All Rights Reserved) may only be looked at for ideas. QuestLineage stays MIT.
- Client calls are guarded (`pcall`, nil checks): frame names and APIs are not verified on every Forever build. Hooks are post-hooks only (`hooksecurefunc`, `HookScript`, `TooltipDataProcessor`).
- Every file must load with a bare namespace table and no client (tests do this).
- Colours: palette and status entries carry a label in slot 4; never pass one straight to `SetVertexColor`/`SetTextColor` as alpha (go through `QL.Theme.Color`, which only takes a numeric slot 4). The real client errors on it; the test mock now does too. Never call `SetVertexColor` on a texture after `T.Gradient`: it overwrites the gradient's vertex colours (that painted the detail panel's backdrop white in game); the mock models this.

## Layout (load order = `QuestLineage.toc`)

- `Core.lua`: namespace `QL` (global `QuestLineage`), `QL.DB()` settings with defaults, `QL.On/Fire` internal messages (`SETTING_CHANGED`, `STATE_CHANGED`, `INDEX_READY`, `LOGIN`), `QL.Event` game events, `/ql` commands.
- `Locale.lua`: `QL.L`, `QL.UseTurkish`, `QL.QuestTitle/QuestObjectives`, fonts.
- `Data.lua`: QuestieDB adaptor, reverse index (`QL.Dependents(id)` = quests needing id, kinds all/any/parent; name list for search; `byZone[area]` = quests whose own zone or giver's zone is that area; `byClass[class bit]` = quests whose class mask names at most three classes; `rewards[quest]` = item ids) built once per session in frame slices (`QL.WhenIndexed(fn)`), `QL.SearchQuests`, `QL.QuestGiver/Ender/Level`. Creature search (setting `creatureSearch`, on; `QL.CreatureSearchOn()`): `index.npcNames` (every NPC's name, from the same NPC pass as services, only while the setting is on; dropped when it is turned off, rebuilt at the next search when turned on again) and `QL.SearchNpcs(text)` (English names, only creatures with spawns, those in the player's zone first, max 20; rows `{id, name, here, count}`).
- `Zone.lua`: uiMapID -> AreaTable id from QuestieDB's support data (`LibQuestieDB.Support.Get("ZoneDB").private`, Lua source strings), subzones folded (`QL.TopArea`), `QL.PlayerZone`, `QL.GroupChains(ids, ctx, keepSingles)` (shared grouping), `QL.ZoneChains(area, ctx)` (chains with a quest in the zone, cached per zone), `QL.ZoneLevels(area, ctx)` (a zone's level band: 10th-90th percentile of the levels of its quests the character could take, nil under 3 quests; QuestieDB has no level range; cached per zone), `QL.ZoneOverview(ctx)` (every zone with quests the character can take: name, continent via `QL.ZoneContinent` (uiMap parents up to mapType 2), level band, counts done/active/available/later; cached against the context table), `QL.ZoneQuestRows(area, ctx)` (a zone's quests, open first, then by level), `QL.ZoneBand(lo, hi, level)` (band colour and relation), `QL.ClassQuests(classFlag)`, `QL.ClassChains(ctx)` (class quests grouped, singles kept, cached per class), `QL.PlayerClass()` (name, file, colour, `CLASS_ICON_TCOORDS`), `QL.ChainProgress(entry, ctx)` (state active/available/toolow/locked/done and the quest to open it at), `QL.ZoneQuestList(area, ctx, opts)` (normal quests: the log anywhere plus what the zone offers now, most XP first; `opts.noChains` drops quests that have a `QL.ChainSummary`, which the Quests tab passes unless setting `questsHideChains` is false; tests turn it off to keep the full fixture list).
- `State.lua`: `QL.Context()` = {level, raceFlag, classFlag, done, log, complete}, cached until a quest-log event. `QUEST_LOG_UPDATE` (several a second in combat) drops the cache at once but fires `STATE_CHANGED` once per burst (0.15 s, `C_Timer.After`); accepted/turned in/removed/level up fire at once. Anything costly hanging off `STATE_CHANGED` runs once per burst, keep it that way.
- `Chain.lua`: pure logic. `QL.BuildChain(id, ctx, opts)` (BFS over all links, node cap 80, one edge per pair with the strongest kind, cycles broken by back edges, layers (generations) by longest path, order within a generation by barycenter sweeps), `QL.NodeStatus`, `QL.ChainSummary` (cached; cleared on state/index/setting changes).
- `Details.lua`: what the detail panel says about a quest: dungeons (`QL.QuestDungeon`: zone or a needed creature's zone in QuestieDB's `ZoneDB.private.dungeons`, incl. alternative areas; kind dungeon/raid/battleground; `QL.DungeonMarkup`), difficulty (`QL.QuestDifficulty`, `QL.GreyLevel`, `QL.LevelMarkup`, `QL.TitleColor` returns r,g,b only), `QL.QuestXP` (support "QuestXP" db), `QL.QuestReputation`, `QL.QuestTasks` (database objectives; an item's picture is the creature that drops it), `QL.LiveObjectives` (logged quests), `QL.QuestStarter/Finisher`, `QL.QuestPlace` (first spawn, the player's zone first; zone names via `C_Map.GetAreaInfo`), `QL.RewardItems` (index.rewards, from items' questRewards), `QL.QuestDescription` (WoWTR's Description in Turkish, else the client for logged quests), `QL.ItemIcon/ItemQuality`. XP: `QL.QuestXPAt(id, level)` (Classic reduction: full up to +5 levels, then 80/60/40/20%, 10% from +10), `QL.ChainXP(ids, ctx)` (remaining at your level, done at full, unknown count), `QL.LevelGain(xp)` (current level from `UnitXP/UnitXPMax`, later levels from Classic's `XP_TO_LEVEL` table, so past the current level it is marked approximate), `QL.GainText`, `QL.XPText`, `QL.FormatNumber`.
- `Nav.lua`: arrow logic, no frames. `QL.QuestTarget(id, ctx)` (pickup: giver spawns; objective: spawns of the unfinished objectives' creatures/objects/item droppers, or `triggerEnd` spots; turnin: finisher spawns), spawns -> `{map, x/100, y/100}` via `QL.AreaUiMap` (QuestieDB `areaIdToUiMapId`), `QL.PlayerPosition`, `QL.ProjectToMap` (world coordinates, same continent), `QL.Locate(target)` (nearest point, yards via `C_Map.GetMapWorldSize`), `QL.Bearing(dx, dy, facing)` = `atan2(-dx, -dy) - facing` (the formula ForeverTrail's arrow uses in game). Client values may be secret (`issecretvalue`): read as nil.
- Abandoning: `QL.AbandonQuest(id)` (State.lua) selects the log line (`QL.QuestLogIndex`: `C_QuestLog.GetLogIndexForQuestID`, `GetQuestLogIndexByID`, else a scan), `SetAbandonQuest`, `AbandonQuest` (as Questie does on this client; else `C_QuestLog.SetSelectedQuest/SetAbandonQuest/AbandonQuest`), puts the log selection back, clears the arrow if it pointed there, fires `QUEST_ABANDONED`. `QL.ConfirmAbandon(id)` asks first with `T.Confirm(title, text, action, onYes)` (Theme.lua, a themed dialog `QuestLineageConfirm`, Escape cancels). `QL.AbandonButton(owner, questOf)` (Current.lua) is a red-on-hover cross shown while the cursor is on its owner and the quest is logged; create it after the owner's own OnEnter/OnLeave (it hooks them, SetScript would drop the hook). Used on the current quest window, its list rows, and the main window's detail buttons ("Abandon quest"; those buttons now wrap to a new line).
- `Theme.lua`: `QL.Theme` palette (dark, teal->violet accent), status and link colours, flat widgets (Fill, Line, Border, Glow, Text, Gradient, Button, CloseButton, Bar, Input, Scroll). New UI uses these, not Blizzard templates.
- `Tree.lua`: the family-tree canvas (`QL.Tree.New(canvas)`, `tree:Draw(chain, focus, animate, minW, minH)`): generations top to bottom, centred (`QL.CardPos`, `QL.CanvasSize`), lines as stem / shared bar / drop; a newly focused quest unfolds generation by generation. Also `QL.FillQuestTooltip`.
- `Inspector.lua`: the detail panel (`QL.Inspector.New(parent)`, `:Show(id, chain)`, `:Clear`): hero with the giver in 3D (`PlayerModel:SetCreature`, idle; icon fallback), sections Objective / Story / Tasks (live progress or database tasks with frozen 3D portraits and item icons) / Start / Turn in / Rewards (XP, reputation, item tiles with quality borders) / Comes after / Leads to / Closes for good, and buttons. Pooled parts laid out top to bottom. 3D portraits use `SetPortraitZoom(1)` (camera on the head) plus `SetCamDistanceScale` to pull back; a partial portrait zoom aims at the chest and cut heads off in game. Models are shown before `SetCreature` and set again when hidden in between (an `OnHide` hook forgets the creature: the client drops a hidden model's mesh) or when no mesh loaded (`GetModelFileID`); an uncached creature is retried at 0.2/0.8/2 s.
- `ZoneMap.lua`: the zone map shown in the middle of the window while a zone is open on the Zones tab (`QL.ZoneMap.New(parent)`, `map:Show(area, ctx, focusId, animate)`): the game's map art (`C_Map.GetMapArtLayers/GetMapArtLayerTextures` base tiles + `C_MapExplorationInfo.GetExploredMapTextures` overlays laid out as the world map does, all guarded and called plainly, never as methods (a `C_Map` function called with `:` gets the table as its map id and returns nothing; the mock now refuses it); without client art the classic files `Interface\WorldMap\<name>\<name>1..12` by uiMap (`QL.ZoneMapArt`); a plain grid when neither; `/ql map [area]` prints what the client gives) in a clipped box with theme tint, vignette and glow; pins from `QL.ZoneMapPins(area, ctx)` (pure: each ready/active/available/toolow quest's `QL.QuestTarget` point on the zone's uiMap nearest the middle of its points; quests closer than ~14 px on the box share a pin (`opts.merge`), `opts.hidden` drops states; returns counts per state too), small dots on a dark edge coloured by state (white ring + halo only when hovered or selected, a count bubble when shared, a larger hit area), popping in one after another; state switches under the map show/hide each state (setting `zoneMapHidden`, `QL.ZoneMapHidden/ToggleZoneMapState`; "level too low" hidden by default; always store a new table); hovering a pin or a quest row in the list (`QL.ZoneMapSpotlight(id)`) brings that pin forward and fades the others; the player's dot breathes while on that map. A pin click opens the quest beside the map (`QL.Open(id, { keepMap = true })`) and points the arrow; "Show chain tree" swaps to the tree, the zone page's "Map" button back. World map (same file, setting `worldMapPins`, on): the zone open on the Zones tab also gets its pins on the game's world map, on its own map and on maps it projects onto (`QL.WorldPinSpots(mapID, area)`, `QL.ProjectToMap`), an overlay on `WorldMapFrame:GetCanvas()` 40 levels under the route's, pins scaled 1/canvas scale and merged within 14 screen pixels (re-laid when the zoom changes), same tooltip/click/state switches; recomputed on map change (`SetMapID` hook), OnShow, STATE/SETTING/INDEX and when another zone is picked (Window.lua `win.worldArea`); the window map's "Open on the world map" button = `QL.OpenZoneOnWorldMap(area)` (not in combat unless already open); test hook `QL.worldPins`. Task places (same file): a click on a task in the detail panel (item, creature, object) points the arrow and calls `QL.ShowTaskSources(kind, id, name, questId)` (Window.lua `spotView`, it wins over the zone map and the tree; "Back" returns; any other `QL.Open` clears it): `map:ShowSpots(view, ctx, animate)` draws every spawn of the sources from `QL.TaskSources(kind, id)` (an item's `npcDrops` (12) and `objectDrops` (8), a creature/object itself, kind `name` = up to 8 creatures from `QL.SearchNpcs` (the creature search; kicker "Creatures"); 300 spawns per source; maps by count) on one map (picked under the map, else the player's, else the fullest), one colour per source with a legend, up to 3 buttons for the other maps; a spot click = `QL.SetArrowPoint`. `Map:Fit(uiMap)` sizes the box and draws the art for both views; `Map:SpotMode(on)` swaps the parts. The detail panel is not redrawn while it already shows the quest (`inspector.shownId`), so its scroll stays. Window.lua keeps `mapMode` (set by a zone row click, cleared by any other `QL.Open(id)`).
- `Window.lua`: the window: header, a navigation rail (`T.RailButton`, icons `Media/nav_*.tga` drawn by `tools/make_icons.py`) choosing the list page, a list panel with "Quests" (normal quests, most XP first; default page), "Chains" (chains of the player's zone, in progress first, follows zone changes), "Class" (the character's class quests: open ones by level, done last; emblem and class colour), "Zones" (every zone with quests for the character, grouped by continent, by level band; your zone marked; a click lists that zone's quests, open ones first, with a back button; setting `zonesArea` = the open zone, the rail button on its own page goes back) and "Search" (as you type; quests, then a "Creatures" section from `QL.SearchNpcs`: an "All on the map" row = `QL.ShowTaskSources("name", text)` and a row per creature = its spawns; `/ql find|bul <name>` = `QL.FindCreatures`) tabs, info bar (chain name, generations, done count; right: chain XP left at your level, its share of your level as text and `T.LevelBar`), tree area (wheel / Shift+wheel / drag), legend, empty states. `QL.Open`, `QL.ToggleWindow`, `QL.RenderWindow(animate)`, `QL.ShowPage`. Setting `page` remembers the tab. The Quests, Chains and Class pages each have a filter box (`page.filter`, debounced re-render): a quest matches by its shown title or English name, a chain when any of its quests matches (`pageQuery`, `questMatches`, `filterChainRows`). Sorting: the Quests, Chains, Class pages and a zone's quest list have XP · Lv · Near buttons beside the filter box (`addSort`, `page:ShowSort(on)` narrows the filter; hidden on the zone list), settings `sortQuests`, `sortChains`, `sortClass`, `sortZoneQuests` = xp | level | distance | nil (nil = the page's own order; a click on the lit button goes back to it); `sortRows(rows, mode, ctx, info)` keeps each row's tier (zone quests: open, then too low/locked, then done/closed; chains: done last) and orders within it, unknown values last; chains go by remaining chain XP, the level and distance of the quest the row opens. Distance order is taken when the list renders (it does not reshuffle while you walk).
- `Arrow.lua`: the heads-up arrow (`QuestLineageArrow`): `QL.SetArrowTarget(id)`, `QL.ClearArrow`, `QL.ArrowQuest`; textures `Media/arrow*.tga` (white, tinted; drawn by `tools/make_arrow.py`, Pillow), arrowhead + facet shade rotated together with `SetRotation` (slim, rounded corners); `QL.UpdateArrow` (every 0.03 s) sets the goal, `QL.StepArrow` (every frame) eases the turn, breathes within 60 yd and plays the arrival pop + ring (without a frame loop, as in tests, the goal applies at once); number and small "yd" are two font strings, soft bands behind title and label; colour by facing (`QL.ArrowColor`); follows the quest's state on `STATE_CHANGED`, stops on `QUEST_TURNED_IN`; target kept per character in `QuestLineageDB.arrowTargets`, position in `arrowPoint`.

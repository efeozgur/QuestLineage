# CLAUDE.md

QuestLineage is a WoW addon (Lua 5.1, Interface 16001, client 1.60.1 "World of Warcraft: Forever"): quest chain trees built on the QuestieDB addon. It is independent of ForeverTrail (a separate repo by the same author). No build step; the repo is linked into `Interface\AddOns\QuestLineage` with a junction, so edits take effect on `/reload` (new files need a full game restart).

## Rules

- **Interface language:** English by default. Turkish is an option that only takes effect while WoWTR is loaded (`QL.UseTurkish()`). Every user-facing string goes through `QL.L("English text")`; add its Turkish to the `TR` table in `Locale.lua`. Quest titles/objectives go through `QL.QuestTitle` / `QL.QuestObjectives` (WoWTR's `QTR_QuestData` first when Turkish, else QuestieDB). Fonts: the addon ships Inter (SIL OFL 1.1, `Media/Fonts/` with `Inter-OFL.txt`): `T.FONT` regular, `T.FONT_BOLD` semibold, set through `T.SetFont(fs, size, bold)` (falls back to WoWTR's Inter, then the game's Arial). The client's Arial Narrow and the game's tooltip font have no Turkish letters on this build, so: never use the game's fonts for QuestLineage text, and never use `GameTooltip` for QuestLineage's own tooltips; use `QL.Tip()` (own tooltip, same SetOwner/AddLine/Show/Hide calls). Item tiles are the exception (the game draws items). Lines QuestLineage adds to the game's NPC tooltip get the theme font and are restored on `OnTooltipCleared`.
- **QuestieDB only through its public API** (`LibQuestieDB.Quest/Npc/Object/Item.Get(id, field)`, `GetAllIds()`, `RequireContract(4)`), via the wrappers in `Data.lua` (`QL.Q/N/O/I`, pcall-guarded). Never read or change QuestieDB's or Questie's files.
- **No third-party code is copied in.** Polestar (GPL) and Queston Forever (All Rights Reserved) may only be looked at for ideas. QuestLineage stays MIT.
- Client calls are guarded (`pcall`, nil checks): frame names and APIs are not verified on every Forever build. Hooks are post-hooks only (`hooksecurefunc`, `HookScript`, `TooltipDataProcessor`).
- Every file must load with a bare namespace table and no client (tests do this).
- Colours: palette and status entries carry a label in slot 4; never pass one straight to `SetVertexColor`/`SetTextColor` as alpha (go through `QL.Theme.Color`, which only takes a numeric slot 4). The real client errors on it; the test mock now does too. Never call `SetVertexColor` on a texture after `T.Gradient`: it overwrites the gradient's vertex colours (that painted the detail panel's backdrop white in game); the mock models this.

## Layout (load order = `QuestLineage.toc`)

- `Core.lua`: namespace `QL` (global `QuestLineage`), `QL.DB()` settings with defaults, `QL.On/Fire` internal messages (`SETTING_CHANGED`, `STATE_CHANGED`, `INDEX_READY`, `LOGIN`), `QL.Event` game events, `/ql` commands.
- `Locale.lua`: `QL.L`, `QL.UseTurkish`, `QL.QuestTitle/QuestObjectives`, fonts.
- `Data.lua`: QuestieDB adaptor, reverse index (`QL.Dependents(id)` = quests needing id, kinds all/any/parent; name list for search; `byZone[area]` = quests whose own zone or giver's zone is that area; `byClass[class bit]` = quests whose class mask names at most three classes; `rewards[quest]` = item ids) built once per session in frame slices (`QL.WhenIndexed(fn)`), `QL.SearchQuests`, `QL.QuestGiver/Ender/Level`.
- `Zone.lua`: uiMapID -> AreaTable id from QuestieDB's support data (`LibQuestieDB.Support.Get("ZoneDB").private`, Lua source strings), subzones folded (`QL.TopArea`), `QL.PlayerZone`, `QL.GroupChains(ids, ctx, keepSingles)` (shared grouping), `QL.ZoneChains(area, ctx)` (chains with a quest in the zone, cached per zone), `QL.ClassQuests(classFlag)`, `QL.ClassChains(ctx)` (class quests grouped, singles kept, cached per class), `QL.PlayerClass()` (name, file, colour, `CLASS_ICON_TCOORDS`), `QL.ChainProgress(entry, ctx)` (state active/available/toolow/locked/done and the quest to open it at), `QL.ZoneQuestList(area, ctx)` (normal quests: the log anywhere plus what the zone offers now, most XP first).
- `State.lua`: `QL.Context()` = {level, raceFlag, classFlag, done, log, complete}, cached until a quest-log event.
- `Chain.lua`: pure logic. `QL.BuildChain(id, ctx, opts)` (BFS over all links, node cap 80, one edge per pair with the strongest kind, cycles broken by back edges, layers (generations) by longest path, order within a generation by barycenter sweeps), `QL.NodeStatus`, `QL.ChainSummary` (cached; cleared on state/index/setting changes).
- `Details.lua`: what the detail panel says about a quest: dungeons (`QL.QuestDungeon`: zone or a needed creature's zone in QuestieDB's `ZoneDB.private.dungeons`, incl. alternative areas; kind dungeon/raid/battleground; `QL.DungeonMarkup`), difficulty (`QL.QuestDifficulty`, `QL.GreyLevel`, `QL.LevelMarkup`, `QL.TitleColor` returns r,g,b only), `QL.QuestXP` (support "QuestXP" db), `QL.QuestReputation`, `QL.QuestTasks` (database objectives; an item's picture is the creature that drops it), `QL.LiveObjectives` (logged quests), `QL.QuestStarter/Finisher`, `QL.QuestPlace` (first spawn, the player's zone first; zone names via `C_Map.GetAreaInfo`), `QL.RewardItems` (index.rewards, from items' questRewards), `QL.QuestDescription` (WoWTR's Description in Turkish, else the client for logged quests), `QL.ItemIcon/ItemQuality`. XP: `QL.QuestXPAt(id, level)` (Classic reduction: full up to +5 levels, then 80/60/40/20%, 10% from +10), `QL.ChainXP(ids, ctx)` (remaining at your level, done at full, unknown count), `QL.LevelGain(xp)` (current level from `UnitXP/UnitXPMax`, later levels from Classic's `XP_TO_LEVEL` table, so past the current level it is marked approximate), `QL.GainText`, `QL.XPText`, `QL.FormatNumber`.
- `Nav.lua`: arrow logic, no frames. `QL.QuestTarget(id, ctx)` (pickup: giver spawns; objective: spawns of the unfinished objectives' creatures/objects/item droppers, or `triggerEnd` spots; turnin: finisher spawns), spawns -> `{map, x/100, y/100}` via `QL.AreaUiMap` (QuestieDB `areaIdToUiMapId`), `QL.PlayerPosition`, `QL.ProjectToMap` (world coordinates, same continent), `QL.Locate(target)` (nearest point, yards via `C_Map.GetMapWorldSize`), `QL.Bearing(dx, dy, facing)` = `atan2(-dx, -dy) - facing` (the formula ForeverTrail's arrow uses in game). Client values may be secret (`issecretvalue`): read as nil.
- `Theme.lua`: `QL.Theme` palette (dark, teal->violet accent), status and link colours, flat widgets (Fill, Line, Border, Glow, Text, Gradient, Button, CloseButton, Bar, Input, Scroll). New UI uses these, not Blizzard templates.
- `Tree.lua`: the family-tree canvas (`QL.Tree.New(canvas)`, `tree:Draw(chain, focus, animate, minW, minH)`): generations top to bottom, centred (`QL.CardPos`, `QL.CanvasSize`), lines as stem / shared bar / drop; a newly focused quest unfolds generation by generation. Also `QL.FillQuestTooltip`.
- `Inspector.lua`: the detail panel (`QL.Inspector.New(parent)`, `:Show(id, chain)`, `:Clear`): hero with the giver in 3D (`PlayerModel:SetCreature`, idle; icon fallback), sections Objective / Story / Tasks (live progress or database tasks with frozen 3D portraits and item icons) / Start / Turn in / Rewards (XP, reputation, item tiles with quality borders) / Comes after / Leads to / Closes for good, and buttons. Pooled parts laid out top to bottom. 3D portraits use `SetPortraitZoom(1)` (camera on the head) plus `SetCamDistanceScale` to pull back; a partial portrait zoom aims at the chest and cut heads off in game.
- `Window.lua`: the window: header, a navigation rail (`T.RailButton`, icons `Media/nav_*.tga` drawn by `tools/make_icons.py`) choosing the list page, a list panel with "Quests" (normal quests, most XP first; default page), "Chains" (chains of the player's zone, in progress first, follows zone changes), "Class" (the character's class quests: open ones by level, done last; emblem and class colour) and "Search" (as you type) tabs, info bar (chain name, generations, done count; right: chain XP left at your level, its share of your level as text and `T.LevelBar`), tree area (wheel / Shift+wheel / drag), legend, empty states. `QL.Open`, `QL.ToggleWindow`, `QL.RenderWindow(animate)`, `QL.ShowPage`. Setting `page` remembers the tab. The Quests, Chains and Class pages each have a filter box (`page.filter`, debounced re-render): a quest matches by its shown title or English name, a chain when any of its quests matches (`pageQuery`, `questMatches`, `filterChainRows`).
- `Arrow.lua`: the heads-up arrow (`QuestLineageArrow`): `QL.SetArrowTarget(id)`, `QL.ClearArrow`, `QL.ArrowQuest`; textures `Media/arrow*.tga` (white, tinted; drawn by `tools/make_arrow.py`, Pillow), arrowhead + facet shade rotated together with `SetRotation`; colour by facing (`QL.ArrowColor`); follows the quest's state on `STATE_CHANGED`, stops on `QUEST_TURNED_IN`; target kept per character in `QuestLineageDB.arrowTargets`, position in `arrowPoint`. Every quest click (Quests, Chains and Search rows, tree cards) points it; the detail panel has Point/Stop buttons. Settings: `arrowColorMode` (direction / accent / custom; `QL.ArrowTint`), `arrowColor` (always store a new table, never write into `QL.defaults`), `arrowScale` (0.5-2, 5% steps), `arrowGlow`; `QL.ApplyArrowSettings`, `QL.ArrowPreview(on)` (the settings page shows a turning sample while open), `QL.ResetArrowPosition`. `/ql arrow [id]` prints every step (frame, target, points, position, distance).
- `Route.lua`: routes over ticked quests. `QL.PlanRoute(ids, ctx)` (each quest one stop = its current `QL.QuestTarget`, points projected to the player's map in yards; nearest neighbour from the player, each stop at its point nearest the previous one, then 2-opt; unmeasurable stops last), `QL.StartRoute/StopRoute/RouteActive/RouteInfo/RouteStop`, selection `QL.RouteSelect/RouteSelected/RouteSelection/ClearRouteSelection`. Re-plans from the player's position when a route quest's stage changes (signature of status + done objectives on `STATE_CHANGED`) or it is handed in (`QUEST_TURNED_IN`); steers the arrow with `route.steering` set, and a hand-picked arrow (`ARROW_CHANGED` from elsewhere) ends the route; while routing, list and card clicks only open quests. Kept per character in `QuestLineageDB.routes`. UI: tick boxes with stop numbers on Quests rows, a footer (Build / Clear / Stop), "Route n/m" on the arrow.
- `MapRoute.lua`: the route on the world map (setting `mapRoute`): an overlay on `WorldMapFrame:GetCanvas()` at the dig-site pin level (ForeverTrail's proven way), `CreateLine` glow + core per leg (next leg accent, later legs violet and fading), flowing `disc` lights, numbered stop badges (`Media/disc|ring.tga`, next one pulsing; scaled 1/canvas scale so they keep their size while zooming; hover = quest tooltip, click = open), the player's dot, a caption on the map frame. Without a route it draws the arrow's quest. `QL.MapRouteStops`, `QL.MapRoutePoints(mapID, w, h)` (pure, tested), `QL.RefreshMapRoute`. Route plans keep the chosen spot per stop (`plan.spots`, `RouteInfo().spots`) so map and arrow agree.
- `Services.lua`: trainers, vendors and services. `QL.SERVICES` (categories, labels, icons, groups), `QL.ClassifyNpc(flags, subName, name)` (pure: `npcFlags` bits and English subtitle words; class trainers as `class:<Class>`, profession trainers as `prof:<Profession>`), indexed in Data.lua's pass (`QL.IndexServiceNpc`, friendly to the player's faction via `friendlyToFaction`; `QL.IndexServiceObject` for objects named "Mailbox") into `index.services[key] = { {kind, id}, ... }`; `QL.NearestServices(key, n)` (projected spots cached per category and player map), `QL.KnownProfessions()` (`GetProfessions` or skill lines), `QL.ClassTrainerKey()`.
- `QuickBar.lua`: the "Where?" bar (`QuestLineageQuickBar`, setting `quickBar`, minimap Shift-click) standing on its own (draggable by its grip, edge or any icon; `quickBarPoint`, reset with the arrow's position reset): 7 icons (repair, inn, flight, class trainer, profession trainer, food, mail) + "more" panel opening below the bar with every category grouped (each known profession its own tile). `QL.GoToService(key)`: nearest via `QL.SetArrowPlace`; a repeated click within 10 s moves to the next nearest. Icons `Media/svc_*.tga` from `tools/make_icons.py`.
- `Toast.lua`: notification cards (`QL.Toast(text, kind)`, kinds info/success/warn/error coloured accent/green/orange/red), stacked downward from `QuestLineageToasts` (draggable, `toastPoint`), slide in, fade after a few seconds (hover holds, click closes). Messages: `QL.Print(msg, kind)` goes to a card while setting `toasts` is on, else the chat; `QL.Chat(msg)` always writes to the chat and is for answers to slash commands (`/ql status`, `help`, `errors`, `arrow`).
- `Current.lua`: the current quest window (`QuestLineageCurrent`, setting `currentQuest`, `currentPoint`, `currentCollapsed`): the arrow's quest (or an arrow place's quest), else the last quest whose counters went up or that was taken; stage, distance, XP, objective rows with counters, bars and a flash on progress. `QL.ObjectiveRows(id, ctx)` matches live objectives to database tasks by name (else order). `QL.CurrentQuest`, `QL.RefreshCurrent`.
- `Plates.lua`: quest badges on nameplates (setting `nameplates`): npc id -> unfinished objective rows of logged quests (creature tasks, and an item task's `npcDrops`), a `quest_mark` badge with the counter beside the plate's health bar; never on forbidden plates; refreshed on `NAME_PLATE_UNIT_ADDED` and quest-log changes. `QL.PlateIndex`, `QL.PlateText`, `QL.RefreshPlates`. Check frame fields with `type(x) == "table"` (the test mock's capitalised fields read as functions).
- `MinimapButton.lua`: button on the minimap rim (left click window, right click settings, drag round the rim; settings `minimapButton`, `minimapAngle`; `QL.MinimapPosition(angle)`).
- `Hooks.lua`: quest log button, NPC tooltip line, quest offer strip (`QL.SummaryText`).
- `Options.lua`: settings page (`QL.OpenOptions`): general toggles, then the Arrow section (colour mode radios, a swatch opening the game's colour picker via `QL.PickColor`, own Slider for size, glow, position reset).

# CLAUDE.md

QuestLineage is a WoW addon (Lua 5.1, Interface 16001, client 1.60.1 "World of Warcraft: Forever"): quest chain trees built on the QuestieDB addon. It is independent of ForeverTrail (a separate repo by the same author). No build step; the repo is linked into `Interface\AddOns\QuestLineage` with a junction, so edits take effect on `/reload` (new files need a full game restart).

## Rules

- **Interface language:** English by default. Turkish is an option that only takes effect while WoWTR is loaded (`QL.UseTurkish()`). Every user-facing string goes through `QL.L("English text")`; add its Turkish to the `TR` table in `Locale.lua`. Quest titles/objectives go through `QL.QuestTitle` / `QL.QuestObjectives` (WoWTR's `QTR_QuestData` first when Turkish, else QuestieDB). One font everywhere: the game's Arial Narrow (`QL.Theme.FONT`, `QL.FontPath`), which has the Turkish letters.
- **QuestieDB only through its public API** (`LibQuestieDB.Quest/Npc/Object/Item.Get(id, field)`, `GetAllIds()`, `RequireContract(4)`), via the wrappers in `Data.lua` (`QL.Q/N/O/I`, pcall-guarded). Never read or change QuestieDB's or Questie's files.
- **No third-party code is copied in.** Polestar (GPL) and Queston Forever (All Rights Reserved) may only be looked at for ideas. QuestLineage stays MIT.
- Client calls are guarded (`pcall`, nil checks): frame names and APIs are not verified on every Forever build. Hooks are post-hooks only (`hooksecurefunc`, `HookScript`, `TooltipDataProcessor`).
- Every file must load with a bare namespace table and no client (tests do this).
- Colours: palette and status entries carry a label in slot 4; never pass one straight to `SetVertexColor`/`SetTextColor` as alpha (go through `QL.Theme.Color`, which only takes a numeric slot 4). The real client errors on it; the test mock now does too. Never call `SetVertexColor` on a texture after `T.Gradient`: it overwrites the gradient's vertex colours (that painted the detail panel's backdrop white in game); the mock models this.

## Layout (load order = `QuestLineage.toc`)

- `Core.lua`: namespace `QL` (global `QuestLineage`), `QL.DB()` settings with defaults, `QL.On/Fire` internal messages (`SETTING_CHANGED`, `STATE_CHANGED`, `INDEX_READY`, `LOGIN`), `QL.Event` game events, `/ql` commands.
- `Locale.lua`: `QL.L`, `QL.UseTurkish`, `QL.QuestTitle/QuestObjectives`, fonts.
- `Data.lua`: QuestieDB adaptor, reverse index (`QL.Dependents(id)` = quests needing id, kinds all/any/parent; name list for search; `byZone[area]` = quests whose own zone or giver's zone is that area) built once per session in frame slices (`QL.WhenIndexed(fn)`), `QL.SearchQuests`, `QL.QuestGiver/Ender/Level`.
- `Zone.lua`: uiMapID -> AreaTable id from QuestieDB's support data (`LibQuestieDB.Support.Get("ZoneDB").private`, Lua source strings), subzones folded (`QL.TopArea`), `QL.PlayerZone`, `QL.ZoneChains(area, ctx)` (chains with a quest in the zone, grouping cached per zone), `QL.ChainProgress(entry, ctx)` (state active/available/toolow/locked/done and the quest to open it at), `QL.ZoneQuestList(area, ctx)` (normal quests: the log anywhere plus what the zone offers now, most XP first).
- `State.lua`: `QL.Context()` = {level, raceFlag, classFlag, done, log, complete}, cached until a quest-log event.
- `Chain.lua`: pure logic. `QL.BuildChain(id, ctx, opts)` (BFS over all links, node cap 80, one edge per pair with the strongest kind, cycles broken by back edges, layers (generations) by longest path, order within a generation by barycenter sweeps), `QL.NodeStatus`, `QL.ChainSummary` (cached; cleared on state/index/setting changes).
- `Details.lua`: what the detail panel says about a quest: `QL.QuestXP` (support "QuestXP" db), `QL.QuestReputation`, `QL.QuestTasks` (database objectives; an item's picture is the creature that drops it), `QL.LiveObjectives` (logged quests), `QL.QuestStarter/Finisher`, `QL.QuestPlace` (first spawn, the player's zone first; zone names via `C_Map.GetAreaInfo`), `QL.RewardItems` (index.rewards, from items' questRewards), `QL.QuestDescription` (WoWTR's Description in Turkish, else the client for logged quests), `QL.ItemIcon/ItemQuality`. XP: `QL.QuestXPAt(id, level)` (Classic reduction: full up to +5 levels, then 80/60/40/20%, 10% from +10), `QL.ChainXP(ids, ctx)` (remaining at your level, done at full, unknown count), `QL.LevelGain(xp)` (current level from `UnitXP/UnitXPMax`, later levels from Classic's `XP_TO_LEVEL` table, so past the current level it is marked approximate), `QL.GainText`, `QL.XPText`, `QL.FormatNumber`.
- `Nav.lua`: arrow logic, no frames. `QL.QuestTarget(id, ctx)` (pickup: giver spawns; objective: spawns of the unfinished objectives' creatures/objects/item droppers, or `triggerEnd` spots; turnin: finisher spawns), spawns -> `{map, x/100, y/100}` via `QL.AreaUiMap` (QuestieDB `areaIdToUiMapId`), `QL.PlayerPosition`, `QL.ProjectToMap` (world coordinates, same continent), `QL.Locate(target)` (nearest point, yards via `C_Map.GetMapWorldSize`), `QL.Bearing(dx, dy, facing)` = `atan2(-dx, -dy) - facing` (the formula ForeverTrail's arrow uses in game). Client values may be secret (`issecretvalue`): read as nil.
- `Theme.lua`: `QL.Theme` palette (dark, teal->violet accent), status and link colours, flat widgets (Fill, Line, Border, Glow, Text, Gradient, Button, CloseButton, Bar, Input, Scroll). New UI uses these, not Blizzard templates.
- `Tree.lua`: the family-tree canvas (`QL.Tree.New(canvas)`, `tree:Draw(chain, focus, animate, minW, minH)`): generations top to bottom, centred (`QL.CardPos`, `QL.CanvasSize`), lines as stem / shared bar / drop; a newly focused quest unfolds generation by generation. Also `QL.FillQuestTooltip`.
- `Inspector.lua`: the detail panel (`QL.Inspector.New(parent)`, `:Show(id, chain)`, `:Clear`): hero with the giver in 3D (`PlayerModel:SetCreature`, idle; icon fallback), sections Objective / Story / Tasks (live progress or database tasks with frozen 3D portraits and item icons) / Start / Turn in / Rewards (XP, reputation, item tiles with quality borders) / Comes after / Leads to / Closes for good, and buttons. Pooled parts laid out top to bottom. 3D portraits use `SetPortraitZoom(1)` (camera on the head) plus `SetCamDistanceScale` to pull back; a partial portrait zoom aims at the chest and cut heads off in game.
- `Window.lua`: the window: header, sidebar with "Quests" (normal quests, most XP first; default page), "Chains" (chains of the player's zone, in progress first, follows zone changes) and "Search" (as you type) tabs, info bar (chain name, generations, done count; right: chain XP left at your level, its share of your level as text and `T.LevelBar`), tree area (wheel / Shift+wheel / drag), legend, empty states. `QL.Open`, `QL.ToggleWindow`, `QL.RenderWindow(animate)`, `QL.ShowPage`. Setting `page` remembers the tab.
- `Arrow.lua`: the heads-up arrow (`QuestLineageArrow`): `QL.SetArrowTarget(id)`, `QL.ClearArrow`, `QL.ArrowQuest`; textures `Media/arrow*.tga` (white, tinted; drawn by `tools/make_arrow.py`, Pillow), arrowhead + facet shade rotated together with `SetRotation`; colour by facing (`QL.ArrowColor`); follows the quest's state on `STATE_CHANGED`, stops on `QUEST_TURNED_IN`; target kept per character in `QuestLineageDB.arrowTargets`, position in `arrowPoint`. The Quests list's row click points it; the detail panel has Point/Stop buttons.
- `MinimapButton.lua`: button on the minimap rim (left click window, right click settings, drag round the rim; settings `minimapButton`, `minimapAngle`; `QL.MinimapPosition(angle)`).
- `Hooks.lua`: quest log button, NPC tooltip line, quest offer strip (`QL.SummaryText`).
- `Options.lua`: settings page (`QL.OpenOptions`).
